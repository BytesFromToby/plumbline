# Decisions: mdtoc
Spec: Planning/specs/mdtoc_spec.md
Date: 2026-06-28

- Standard-library-only Python, no parsing dependencies — rejected pulling in a Markdown library (e.g. `markdown`, `mistune`). The brief needs only ATX heading detection with code-fence awareness, which is a small line scan; a dependency would add install surface for no gain and would parse far more than the spec covers.
- CLI exposed as `python -m mdtoc` (runnable module) rather than an installed console-script entry point — keeps the run/demo command real and dependency-free without requiring a `pip install` step before `inspector` can run it. An entry-point can be added later via packaging without changing behaviour.
- `~~~` fences honoured alongside ``` ``` ``` ``` fences (recorded as an Assumption) — the brief named only backtick fences, but CommonMark treats `~~~` as an equivalent fence; ignoring it would mis-classify a `#` inside a `~~~` block as a heading. Cheap to revert if only backticks are wanted.
- Setext headings explicitly out of scope, not an error — the brief said ATX only. Treating `===`/`---` underlines as a hard error would surprise users with valid Markdown; silently ignoring them matches "finds ATX headings" literally.
- No size-flag concern — 5 feature blocks, well under the 6-feature / ~500-line / ~150-line-per-feature thresholds.
