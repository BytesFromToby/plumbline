---
name: scaffold
description: Bootstrap a project's structure — convention folders, a CLAUDE.md contract (test command, run/demo command, blueprint format), and a starter spec with the "Done when" format. Run once per project.
---

## When to use this skill
- Starting a new project that has none of the `Planning/` structure yet.
- Adding the convention scaffolding to an older project that predates it.

Run once. If structure already exists, scaffold fills only what is missing — it never overwrites your files.

---

## What it creates

**Folders:**
- `Planning/specs/` — specs (the single source of truth)
- `Planning/specs/archive/` — superseded spec versions, named `[feature]_spec_YYYY-MM-DD.md`
- `Planning/blueprints/` — per-feature build plans (generated by foreman)
- `Planning/decisions/` — decision docs (see the **Change rules** in CLAUDE.md, Full Path)
- `docs/changelog/` — changelog (see the **Change rules** in CLAUDE.md)
- `output/` — skill output. Subfolders are created lazily by the skills that write them: `output/inspect/` (inspector reports + screenshots), `output/deviations/` (builder deviation rollups); `walkthrough` logs land at the top level.

Do **not** create a `tools/` folder. `walkthrough` creates it lazily only if it writes a helper script — nothing empty gets pre-created.

**Files:**
- `CLAUDE.md` — the project contract (created only if missing; otherwise append missing sections)
- `Planning/specs/_TEMPLATE.md` — starter spec showing the "Done when" format

---

## Step 1 — Check what exists

List the project root. For each folder and file above, note present vs. missing. Never overwrite an existing file. If everything already exists, report that and stop.

---

## Step 2 — Determine the stack contract

Find two commands. Try to infer them from the project first (`package.json` scripts, `pyproject.toml`, `Makefile`, entry points). If you cannot infer either with confidence, ask the user — one at a time:

1. **Test command** — how the project's tests run.
2. **Run/demo command** — how to launch the thing so a human can *see* it work: dev server, CLI entrypoint, or an example invocation.

These two go into CLAUDE.md. The run/demo command is what `inspector` depends on, so it must be real — not a placeholder.

If the run/demo command launches a **web UI**, also record a **UI evidence tool** — default `playwright (python)`. `inspector` uses it to drive the browser and capture screenshots. Omit this line for non-UI stacks (CLI, library).

---

## Step 3 — Create folders

Create any missing folders from the list above.

---

## Step 4 — Write CLAUDE.md

If `CLAUDE.md` does not exist, create it from the contract below. If it exists, append only the sections it is missing — do not touch existing content.

```
# [Project Name]

## Stack
[language / framework]

## Commands
- Test: `[test command]`
- Run/demo: `[how to launch it so behaviour is visible]`
- UI evidence tool: `playwright (python)`   # web UI stacks only — inspector uses it to drive + screenshot; omit for CLI/library

## Specs
Source of truth. Live in Planning/specs/, named `[feature]_spec.md`. Each feature carries inline
**Done when:** items tagged [automated] or [human-required].

## Blueprints
Per-feature build plans generated by foreman, in Planning/blueprints/[feature]_BP.md.
Format: slices of ordered steps, one concern each, with Build/Test/Done When/Stuck If per step.
The builder follows the blueprint; inspector checks the spec's Done when items when done.

## Change rules
Every code, data, or structure change picks a path.

**Quick Path** — use only if ALL hold: no files added/removed/renamed, no schema/data-model
change, no core-logic change, nothing a future reader would need explained.
1. Write/edit the code  2. Run the test command  3. Add a changelog entry under today's date
4. If tracked on a blueprint, mark the item done.

**Full Path** — everything else (new features, schema, core logic, files added/removed/renamed,
any choice worth recording):
1. Update the spec if one exists — if the change reshapes it, run **architect** instead
2. Write/edit the code  3. Run the test command  4. Run **inspector** if the change is tracked
by a blueprint  5. Add a changelog entry  6. Update this CLAUDE.md file map if files moved
7. Write a decision doc to Planning/decisions/ if a non-obvious choice was made (what + why)
8. If tracked on a blueprint, mark the item done.

Changelog: docs/changelog/changelog.md — grouped by date, with Added / Changed / Fixed / Removed.
Decision docs: Planning/decisions/.  Skill output: output/.
```

---

## Step 5 — Seed the spec template

Write `Planning/specs/_TEMPLATE.md`:

```
# Spec: [Feature or Project Name]

One paragraph: what this does.

## Scope
- Does: ...
- Does NOT: ...

## Feature: [Name]
What it does.

- Input: ...
- Output: ...

**Done when:**
- [observable pass/fail criterion]  `[automated]`
- [another observable criterion]  `[automated]`
- [criterion only a human can judge — layout, copy, feel]  `[human-required]`

<!-- Repeat a Feature block per feature. Every feature ends with a **Done when:** block.
     inspector reads these literal markers — keep the "**Done when:**" heading and the
     `[automated]` / `[human-required]` tags exact. -->
```

---

## Step 6 — Report

List what was created vs. what was already present. Then tell the user:

1. Run **architect** to write the spec, or copy `Planning/specs/_TEMPLATE.md` and fill it in by hand.
2. Run **foreman** to generate the blueprint from the spec.
3. Run **builder** slice by slice.
4. Run **inspector** to prove the "Done when" items are met.
